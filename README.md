# type

D를 위한 커스텀 수치 타입 라이브러리. 분수(`fra`)와 IEEE 754-2008 10진 부동소수점 두 인코딩(`bid`, `dpd`)을 제공합니다.

## 설치

`dub.json`에 추가:

```json
"dependencies": {
    "rnjswldbf_2014": "~>0.1.0"
}
```

```d
import type.type;
```

## 핵심 타입

| 타입 | 용도 | 정밀도 |
|------|------|--------|
| `fra` | 유리수 분수 (`num`/`den`, `BigInt`) | 임의정밀도, 정확 |
| `bid` | 10진 부동소수점, 계수를 `BigInt`로 저장 | 임의정밀도, 정확 |
| `dpd` | 같은 값을 10비트 declet으로 압축 저장 | 임의정밀도, 정확 |

`bid`와 `dpd`는 **같은 값을 다른 방식으로 저장**할 뿐, 연산 결과는 동일합니다. IEEE 754-2008이 정의한 두 가지 10진 인코딩에 각각 대응합니다.

- **BID** (Binary Integer Decimal): 계수를 이진 정수 하나로 저장
- **DPD** (Densely Packed Decimal): 10진수 3자리를 10비트로 압축해 저장

## 선언

세 타입 모두 정수·문자열·소수 리터럴로 바로 선언됩니다.

```d
bid a = 1;               // 정수
bid b = "1.5";           // 문자열
bid c = 1.5;             // 소수 리터럴
bid d = 0.12;            // 0.12 (내부 double이 0.11999...여도 정확히 복원)

dpd e = "2.25";
fra f = 5;               // 5/1
fra g = "3/4";           // 3/4
fra h = "0.75";          // 3/4 (약분됨)
```

### ⚠️ 17자리 규칙

따옴표 없는 소수 리터럴은 **유효숫자 약 17자리까지만** 정확합니다.

```d
bid ok  = 3.37981234;    // 9자리  -> 3.37981234           정확
bid bad = 0.04714038928745574865871078547801351068934;
                         // 41자리 -> 0.04714038928745575  잘림!
bid good = "0.04714038928745574865871078547801351068934";
                         // 41자리 전부 정확
```

D 문법상 따옴표 없는 `1.5`는 컴파일 단계에서 이미 `double`로 변환된 뒤 생성자에 전달됩니다. 라이브러리는 "그 double과 정확히 같은 비트값으로 다시 파싱되는 가장 짧은 소수 문자열"을 찾아 복원하므로(Python의 `Decimal(str(x))`와 같은 기법) 짧은 리터럴은 원래 쓴 그대로 잡히지만, `double`이 애초에 담지 못한 자릿수는 되살릴 수 없습니다.

**17자리를 넘는 정밀도가 필요하면 반드시 따옴표를 쓰세요.**

## 연산

```d
bid x = "1.5";

x + 1            // 2.5   — 일반 숫자와 혼용 가능
1 + x            // 2.5   — 좌우 어느 쪽이든
x - "0.5"        // 1.0
x * 3            // 4.5
x > 1            // true
x == "1.50"      // true  — 값 비교 (표기가 달라도 동일)
```

나눗셈은 자릿수를 명시합니다 (반올림: round-half-up):

```d
bid one = 1, three = 3;
one.divide(three, 21)     // 0.333333333333333333333  (21자리)
```

`fra`와도 정확히 상호운용됩니다 (double 근사를 거치지 않고 `계수 × 10^지수`를 약분):

```d
fra half = fra(1, 2);
bid quarter = "0.25";
half + quarter            // 3/4
```

`num`/`den`이 `BigInt`라 자릿수 제한이 없습니다. 41자리 소수도 정확히 분수로 들어가고, `toBid(자릿수)`로 되돌릴 수 있습니다.

```d
fra f = getFra(bid("0.04714038928745574865871078547801351068934"));
f.toBid(41)      // 원본 소수와 정확히 일치

-f               // 단항 마이너스
f > fra("1/2")   // 비교
f == fra("6/8")  // 값 비교 (약분 전후 무관)
f / fra("1/2")   // 나눗셈
```

## DPD 비트 인코딩

`dpd`는 값을 3자리씩 묶어 10비트 declet에 압축합니다.

```d
dpd v = "0.476190476190476190476";
v.digits.length      // 21
v.pack()             // ushort[7] — 10비트 declet 7개
v.pack()[0]          // 0b1001110110
```

| 메서드 | 설명 |
|--------|------|
| `pack()` | 자릿수를 declet 배열로 압축 |
| `dpd.unpackDigits(declets)` | declet 배열을 자릿수로 복원 |
| `toBid()` / `dpd.fromBid(b)` | `bid`와 상호 변환 |
| `bcdToDpd(d2,d1,d0)` | 3자리 → 10비트 (저수준) |
| `dpdToBcd(declet, ...)` | 10비트 → 3자리 (저수준) |

인코딩/디코딩은 스펙 저자 Mike Cowlishaw가 공개한 불리언 공식을 그대로 구현했으며, **0~999 전 조합(1000개)에 대한 왕복 테스트**로 검증됩니다.

## 방정식 풀이

`solve(변수명, 방정식)` — 1~4차 방정식의 해를 구합니다.

```d
solve("x", "x + 5 = 12")             // ["x: 7"]
solve("x", "x^2 - 5x + 6 = 0")       // ["x: 3", "x: 2"]
solve("x", "x^2 = 2x + 3")           // ["x: 3", "x: -1"]   — 양변에 항이 있어도 됨
solve("x", "x^3 - 6x^2 + 11x - 6 = 0")  // ["x: 3", "x: 2", "x: 1"]
solve("y", "2y - 8 = 0")             // ["y: 4"]            — 변수명 자유
```

**4차** (Ferrari 방법):

```d
solve("x", "x^4 - 10x^3 + 35x^2 - 50x + 24 = 0")  // ["x: 4", "x: 3", "x: 2", "x: 1"]
solve("x", "x^4 - 5x^2 + 4 = 0")     // ["x: 2", "x: 1", "x: -1", "x: -2"]
solve("x", "x^4 - 1 = 0")            // ["x: 1", "x: -1", "x: 0 + 1i", "x: 0 - 1i"]
```

표기는 `2*x`, `2x`, `x^2` 모두 되고 공백은 자유입니다. 우변을 생략하면 `= 0`으로 봅니다. 근은 실근을 내림차순으로 먼저, 그다음 복소근 순으로 나옵니다.

**복소근도 반환합니다:**

```d
solve("x", "x^2 + 1 = 0")   // ["x: 0 + 1i", "x: 0 - 1i"]
solve("x", "x^3 = 8")       // ["x: 2", "x: -1 + 1.732050808i", "x: -1 - 1.732050808i"]
solve("x", "x^4 + x = 0")   // ["x: 0", "x: -1", "x: 0.5 + 0.8660254038i", "x: 0.5 - 0.8660254038i"]
```

중근은 한 번만 나옵니다 (`x^3 - 3x^2 + 3x - 1 = 0` → `["x: 1"]`, `x^4 = 0` → `["x: 0"]`). 해가 없거나 무한하면 `["no solution"]` / `["infinitely many solutions"]`를 반환하고, **5차 이상은 조용히 틀린 답을 주는 대신 예외를 던집니다.**

> `solve()`의 내부 계산은 `double` 기반이라 약 17자리까지입니다. 해는 부동소수점 잡음을 정리해 출력하므로 `1.9999999999999998` 대신 `2`로 나옵니다.

### 임의정밀도 풀이

`solvePrecise(변수명, 방정식, 자릿수)` — 소수점 이하 원하는 자릿수만큼 정확하게 풉니다.

```d
solvePrecise("x", "x^2 - 2 = 0", 50)
// ["x: 1.41421356237309504880168872420969807856967187537695",
//  "x: -1.41421356237309504880168872420969807856967187537695"]

solvePrecise("x", "x^3 - 2 = 0", 50)[0]
// "x: 1.25992104989487316476721060727822835057025146470151"

solvePrecise("x", "x^3 - 3x + 1 = 0", 20)
// ["x: 1.53208888623795607040", "x: 0.34729635533386069770",
//  "x: -1.87938524157181676811"]

solvePrecise("x", "x^4 - 2 = 0", 45)[0]   // 2^(1/4)
// "x: 1.189207115002721066717499970560475915292972092"
```

계수부터 `bid`로 정확히 파싱합니다. 1차·2차·중근 3차는 닫힌 형태로 정확히 풀고, 나머지 3차와 4차는 근사값을 씨앗으로 **정확 산술 Newton법**을 반복해 요구 자릿수까지 수렴시킵니다 (복소근은 복소 Newton법). 최종 정밀도는 `double`과 무관합니다.

**실근을 `dpd` 값으로 받기:**

```d
auto roots = solveRealRoots("x", "x^2 - 2 = 0", 45);
roots[0].toString()        // 1.414213562373095048801688724209698078569671875
roots[0].digits.length     // 46
roots[0].pack().length     // 16   — 10비트 declet
```

복소근은 `solvePrecise`가 문자열로 반환하고, `solveRealRoots`는 실근만 골라 돌려줍니다.

### 임의정밀도 제곱근·세제곱근·반올림

`bid`와 `dpd` 모두 값에서 바로 호출합니다. 인자는 소수점 이하 자릿수입니다.

```d
dpd two = 2;
two.sqrt(40)    // 1.4142135623730950488016887242096980785696
two.cbrt(40)    // 1.2599210498948731647672106072782283505702
two.sqrt(40).round(10)   // 1.4142135624

bid b = 2;
b.sqrt(60)      // 1.414213562373095048801688724209698078569671875376948073176679
```

> `sqrt`/`cbrt`는 **절사**합니다 (구한 근이 실제값을 넘지 않도록). 반올림한 값이 필요하면 한 자리 더 구해서 `round()`를 쓰세요 — `two.sqrt(45).round(40)`.

### 임의정밀도 로그

```d
bid two = 2;
two.ln(50)        // 0.69314718055994530941723212145817656807550013436026
two.log10(50)     // 0.30102999566398119521373889472449302676818988146211

bid(1000L).log10(40)         // 3  (정확히 떨어짐)
bid(1024L).log2(40)          // 10
bid(81L).log(bid(3L), 40)    // 4   — 임의 밑
```

`dpd`에서도 똑같이 `.ln()`, `.log10()`, `.log2()`, `.log(base, scale)`를 쓸 수 있습니다. 인수를 반복 제곱근으로 1 근처까지 줄인 뒤 `ln(x) = 2·artanh((x-1)/(x+1))` 급수로 계산하므로, 아주 크거나 작은 값도 자릿수 손실 없이 처리합니다 (`ln(10¹⁰⁰) = 100·ln(10)`이 정확히 성립).

> 로그는 **양수**에만 정의됩니다. 0이나 음수, 밑이 1인 경우 예외를 던집니다.

### 상수와 삼각함수

```d
bidPi(50)   // 3.14159265358979323846264338327950288419716939937511
bidE(50)    // 2.71828182845904523536028747135266249775724709369996

bid one = 1;
one.sin(50)    // 0.84147098480789650665250232163029899962256306079837
one.cos(50)    // 0.54030230586813971740093660744297660373231042061792
one.tan(50)    // 1.55740772465490223050697480745836017308725077238152
one.atan(50)   // 0.78539816339744830961566084581987572104929234984378
one.asin(30)   // pi/2
bid(0L).acos(30)  // pi/2
```

`dpd`에서도 동일한 메서드를 쓸 수 있습니다. π는 Machin 공식, `e`는 계승 급수, 삼각함수는 2π로 각도를 축소한 뒤 Taylor 급수로 계산합니다. 큰 각도도 축소 단계에서 자릿수를 넉넉히 잡으므로 `sin(1000)`처럼 먼 각도도 요구한 자릿수까지 정확합니다.

> `asin`/`acos`는 `|x| ≤ 1`에서만 정의되며, 벗어나면 예외를 던집니다. `tan`은 `cos`가 0인 지점에서 예외를 던집니다.

동일 기능의 자유 함수와 저수준 함수도 있습니다.

| 함수 | 설명 |
|------|------|
| `bidSqrt(v, scale)` / `bidCbrt` / `bidRound` | 위 메서드의 자유 함수 형태 |
| `bidLn(v, scale)` / `bidLog10` / `bidLog2` / `bidLog(base, v, scale)` | 로그의 자유 함수 형태 |
| `bidPi(scale)` / `bidE(scale)` | π, e 상수 |
| `bidSin` / `bidCos` / `bidTan` / `bidAtan` / `bidAsin` / `bidAcos` | 삼각함수의 자유 함수 형태 |
| `refineRoot(coeffs, guess, m, scale)` | Newton법 근 정밀화 (`m`은 중근 차수) |
| `refineComplexRoot(coeffs, re, im, scale)` | 복소근 Newton법 정밀화 |
| `isqrt(n)` / `icbrt(n)` | `BigInt` 정수 제곱근·세제곱근 |

> 문자열 선언은 **일반 소수 표기만** 받습니다. `bid("1e100")` 같은 지수 표기는 예외를 던집니다 — `bid`는 모든 자릿수가 유효숫자라서 값을 그대로 적어야 합니다.

## 기타 타입

### `dec` — 인코딩을 고르는 10진수

`mode`가 실제 저장 표현을 결정합니다. 값은 `bid`로 정확히 보관하므로 연산도 정확합니다.

```d
dec a = dec("0.1", "bid");
dec b = dec("0.1", "dpd");
a == b                      // true — 같은 값, 다른 표현
b.declets()                 // 10비트 declet 배열 (dpd 모드에서만)

(dec("0.1") + dec("0.2")).toString()      // 0.3(bid)  — double이 아님
dec("1").divide(dec("7"), 21)             // 0.142857142857142857143(bid)
fra(1, 2) + dec("0.25")                   // 3/4 — 정확히 상호운용
```

### `posit` — 실제 Type III unum

`bits`(2~32)가 실제 비트 폭입니다. 값은 posit 격자로 반올림되며, 1 근처에서 정밀도가 가장 높고 극단으로 갈수록 줄어듭니다(tapered precision). 표준대로 `es = 2`입니다.

```d
posit(1.0, 8).val        // 1        정확히 격자 위
posit(0.1, 8).val        // 0.101562  8비트 격자로 반올림
posit(0.1, 32).val       // 0.1 에 훨씬 가까움
posit(0.1, 8).encoding() // 0x25     실제 비트 패턴

positDecode(0b01000000, 8)   // 1
positDecode(0b00111000, 8)   // 0.5
positDecode(0b10000000, 8)   // NaR (nan) — posit의 유일한 예외값
```

`NaN`이 하나(NaR)뿐이고 부호 있는 0이 없는 것도 posit 규격 그대로입니다. 무한이 없으므로 **0으로 나누면 NaR**이고, 유한한 큰 값은 무한으로 넘어가지 않고 **maxpos로 포화**합니다.

```d
posit(1.0, 16) / posit(0.0, 16)    // NaR
posit(1e30, 16).val               // maxpos (포화)
posit(double.nan, 16) + posit(1.0, 16)   // NaR 전파
```

**검증 범위**: 규격에 공개된 비트 패턴 대조, `maxpos = 16^(n-2)`·`minpos` 독립 유도, posit8 256개 전수(왕복·단조성·2의 보수 대칭성), posit16 65536개 전수 단조성, 그리고 posit16/posit32 각각 곱셈·덧셈·나눗셈 60만 연산을 `BigInt` 유리수로 계산한 정확값과 대조(오반올림 0건).

**알려진 제약:**
- `es = 2` 고정입니다 (2022 표준). 폭마다 `es`가 달랐던 이전 관례(posit8은 `es=0` 등)를 기대하면 값이 다릅니다.
- 폭은 2~32비트입니다. posit64는 미지원입니다.
- 산술은 `double`로 계산한 뒤 격자에 반올림합니다. posit32는 정확한 결과가 최대 56 유효비트까지 필요해 `double`의 53비트를 넘을 수 있어, 원리적으로 이중 반올림이 가능합니다(60만 연산에서 관측되지 않았지만 불가능하다고 증명한 것은 아닙니다). posit8/posit16은 유효비트가 13비트 이하라 이 문제가 없습니다.
- 정확한 내적을 위한 quire 누산기는 구현하지 않았습니다.

### `dfloat` — 폭을 고르는 이진 부동소수점

`precisionBytes`가 실제 정밀도를 결정합니다: `4`는 float로 좁히고, `8`/`10`은 double 그대로 둡니다. 연산할 때마다 같은 폭으로 다시 반올림됩니다.

```d
// format("%.20f", ...) 로 봐야 차이가 보입니다 — writeln 은 둘 다 "0.1" 로 줄여 찍습니다
dfloat(0.1, 4).val   // 0.10000000149011611938  (float 정밀도)
dfloat(0.1, 8).val   // 0.10000000000000000555  (double)
dfloat(0.1, 4).val != dfloat(0.1, 8).val           // true
(dfloat(0.1, 4) + dfloat(0.2, 4)).precisionBytes   // 4 유지
```

> 입력이 이미 `double`이므로 폭은 **좁힐 수만** 있습니다. `10`은 없던 정밀도를 되살리지 못하고 `8`과 같은 결과가 됩니다.
